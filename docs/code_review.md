# Code Review - Member Management

Full-repo review covering backend, frontend, tests, tooling, git hygiene, and
docs. Findings are grouped by severity. Each has a concrete action. A prioritized
checklist is at the end.

Reviewed at commit `f4bf6a6`. Standards applied: the four rules in root
`AGENTS.md` (latest idiomatic libs; simplify, no over-engineering, no speculative
defensive code; be concise; root-cause before fix).

> **Status:** all Critical/High/Medium items and every quick Low/test item have
> been applied. Backend 15/15 tests pass, frontend 36/36 + 5 E2E pass, lint and
> build are clean. Remaining deferrals are listed at the end of the checklist.
> The finding write-ups below are kept as-is for context; the checklist reflects
> what was done.

---

## Summary

The app is a working MVP: CRUD flows, AI chat, and a clean proxy architecture
that keeps the OpenRouter key server-side. Code is small and readable. The main
problems are not architectural:

1. **Git hygiene** - the SQLite database and build caches are committed.
2. **Defensive-code sprawl** on the frontend that the project's own standards
   forbid (redundant try/catch, dual response-shape handling, over-built helpers).
3. **A few real bugs** - non-numeric member id hangs the edit page, AI JSON in
   markdown fences silently no-ops, delete-error leaves the modal stuck.
4. **Stale docs** - `backend/AGENTS.md`, `frontend/README.md`, and
   `backend/backend.http` describe things that do not exist.
5. **Thin, partly broken tests** - the E2E spec cannot pass as written.

Nothing here blocks the MVP, but items in Critical/High should be fixed before
the repo is shared or built on.

## Critical

### C1. The SQLite database is committed to git
`backend/members.db`, `backend/members.db-shm`, `backend/members.db-wal` are all
tracked (`git ls-files`). These are runtime artifacts: they change on every run,
produce noise diffs, will cause merge conflicts, and are regenerated by
`EnsureCreated()` + seeding anyway.

**Action:**
- Add to root `.gitignore`: `*.db`, `*.db-shm`, `*.db-wal`
- `git rm --cached backend/members.db backend/members.db-shm backend/members.db-wal`
- Commit.

### C2. Edit page hangs on a non-numeric id
`frontend/src/app/members/[id]/page.tsx:18` does
`const memberId = parseInt(params.id as string, 10)`. For `/members/abc`,
`memberId` is `NaN`, the `if (memberId)` guard on line 33 is false, `fetchMember`
never runs, and `isLoading` stays `true` forever - permanent "Loading member...".

**Action:** guard the parse - if `Number.isNaN(memberId)` render the
"Member not found" alert (set `isLoading` false), don't attempt a fetch.

## High

### H1. AI action silently dropped when the model fences its JSON
`frontend/src/app/api/chat/route.ts:77-81` does `JSON.parse(content)` and on any
throw falls back to `{ action: null, message: content }`. `openai/gpt-oss-120b`
frequently wraps JSON in ```` ```json ```` fences or adds a prose preamble, so a
valid create/edit/delete instruction becomes a plain chat message and **the
member operation never happens** - with no error shown to the user.

**Action:** before parsing, extract the first `{...}` block (strip ``` fences and
surrounding prose). If parsing still fails, return the fallback. Add a test with
a fenced response.

### H2. Delete error leaves the modal in a broken state
`frontend/src/app/page.tsx:46-61` - on delete failure `setError(...)` is called
but `setDeleteModalOpen(false)` is not, so the modal stays open over a
page-level error Alert the user cannot see behind it, with the confirm button
re-enabled.

**Action:** on error either close the modal, or (better) render the error
*inside* the Modal and keep it open for retry. Pick one and make add/edit
consistent with it.

### H3. Frontend `memberService` violates the "no defensive programming" standard
Every method in `frontend/src/services/memberService.ts` is wrapped in
`try { ... } catch (error) { console.error(...); throw error; }`. The catch adds
nothing but a console line and doubles the function length. `getAllMembers` also
carries `result.data || result` plus `if (!Array.isArray(members)) throw` -
handling a response shape the backend never sends.

**Action:** delete the try/catch wrappers; let errors propagate. Expect the real
contract (`{ data }`) and drop the `|| result` / `Array.isArray` fallbacks. This
roughly halves the file. Same treatment for the `result.data || result` fallback
in `getMember`/`createMember`/`updateMember`.

### H4. E2E spec cannot pass as written
`frontend/src/__tests__/e2e/navigation.spec.ts`:
- `page.click('text=View Members')` - the header link text is "Members"
  (`components/Header.tsx:26`), not "View Members".
- `expect(page).toHaveURL('/members')` - `/members` immediately
  `redirect('/')`s (`app/members/page.tsx`), so the URL is `/`.
- `playwright.config.ts` starts only the frontend dev server; `page.goto('/')`
  then calls the backend proxy, which fails if the backend is not running.

**Action:** fix the selectors/URLs, and either add the backend to `webServer` or
mock `/api/members` in the test. Then expand to real add/edit/delete/AI flows
(see T1).

### H5. `backend/AGENTS.md` and `frontend/README.md` describe code that does not exist
- `backend/AGENTS.md`: claims a global error-handling middleware and a
  `{ error, code }` envelope for *all* errors (only handled 404/400 produce it);
  "Migrations: Applied automatically" (it is `EnsureCreated()`, no migrations);
  curl examples on port 5000 (real port 5156); `NEXT_PUBLIC_API_BASE_URL`
  default `http://localhost:5000` (real default `http://localhost:5156/api`);
  references `backend.http` with member examples (see H6).
- `frontend/README.md`: `.env.local` (real: repo-root `.env`), port 5000,
  `hooks/useMember.ts` (does not exist), axios (not a dependency).

**Action:** rewrite both to match reality, or delete the redundant prose and
point at `docs/PLAN.md` (now accurate) + `CLAUDE.md`.

### H6. `backend/backend.http` is the unmodified template
It contains only `GET {{backend_HostAddress}}/weatherforecast/` - an endpoint
that does not exist. `backend/AGENTS.md` tells developers to use this file to
test member endpoints.

**Action:** replace its contents with the five member requests (GET list, GET by
id, POST, PUT, DELETE) against `http://localhost:5156/api/members`.

## Medium

### M1. No global exception handling on the backend
`backend/Program.cs` has no `UseExceptionHandler`. An unhandled exception (DB
locked, disk full, bug) returns a bare 500 - a stack trace in Development, an
empty body in Production - not the `{ error, code }` shape the frontend parses,
and with no structured log of the failure.

**Action:** add a minimal exception handler that logs the exception with request
context and returns `{ error: "Internal server error", code: "INTERNAL_ERROR" }`.
Keep it short - this is not a reason to build a middleware class hierarchy.

### M2. `members/[id]/route.ts` GET swallows the backend error body
`frontend/src/app/api/members/[id]/route.ts:18-23` returns a generic
`{ error: 'Failed to fetch member' }` on a non-ok backend response, while the
POST/PUT handlers forward the backend's `errorData`. `memberService.getMember`
then also replaces it with `'Failed to fetch member'`. A 404 on the edit page
shows a generic string instead of "Member not found".

**Action:** forward the backend response body and status in the GET handler, as
POST/PUT already do. Make `getMember` parse `error.error` like the other methods.

### M3. `MemberForm` success/reset logic is unreachable
`frontend/src/components/MemberForm.tsx:76-89` sets a `successMessage` and resets
fields after `onSubmit`, but both callers (`members/new`, `members/[id]`)
`router.push('/')` inside `onSubmit`, so the component unmounts first. The
`successMessage` Alert, the `<Alert type="success">` branch, and the field-reset
block are dead code.

**Action:** decide the pattern - either navigate away (delete the
success/reset code) or stay and show confirmation (remove the `router.push`).
Navigating away is simpler and matches the current UX.

### M4. Redundant no-op try/catch in the page components
`members/new/page.tsx:14-18` and `members/[id]/page.tsx:39-45` both wrap the
service call in `try { ... } catch (error) { throw error }`. Pure noise;
`MemberForm.handleSubmit` is the real error handler.

**Action:** remove both try/catch blocks; call the service directly.

### M5. `dateFormatter.ts` is over-built for its input
`frontend/src/utils/dateFormatter.ts` is 36 lines of nested try/catch,
`isNaN` checks, and `console.warn`/`console.error` for what is a split-and-format
on always-well-formed ISO strings from the backend.

**Action:** reduce to the happy path plus the `if (!dateString) return '-'`
guard. Drop the logging. ~8 lines.

### M6. Home-page "stats" are cosmetic filler
`app/page.tsx:87-140` - "Last Updated" always shows `new Date()` (today,
regardless of data), "Status" is a hardcoded "Active". Misleading, and counter to
"no extra features - focus on simplicity."

**Action:** keep "Total Members" (it is real), remove the other two cards, or
replace "Last Updated" with a real value if one is worth surfacing.

### M7. `Modal` accessibility
`components/Modal.tsx` has no `role="dialog"`/`aria-modal`, no Escape-to-close, no
focus trap or initial focus, no body-scroll lock, and the backdrop is not
clickable to dismiss.

**Action:** add `role="dialog" aria-modal="true"`, an Escape key handler, and
backdrop-click close. Focus trap can wait unless accessibility is in scope.

### M8. Full member PII sent to OpenRouter, more than the types imply
`app/api/chat/route.ts:63` serializes the member objects into the system prompt.
`aiService.chat` passes full `Member[]` (name, DOB, postal code, mobile), even
though the route's `MemberSummary` type lists only id/first/surname - the extra
fields still land in the prompt.

**Action:** in `buildSystemPrompt` (or before the POST), project members down to
`{ id, firstName, surname }` so only what the model needs for identification
leaves the system. Document that member identifiers are sent to OpenRouter.

### M9. `/api/chat` is an unauthenticated proxy to a paid API
Anyone who can reach the dev server can spend OpenRouter credits. Acceptable for
local MVP, but should be a known risk.

**Action:** note it in `docs/PLAN.md` "Known gaps" (already partly there); if the
app is ever deployed, add at minimum a shared-secret check or rate limit.

### M10. No `.env.example` and no root README
A new developer cloning the repo has no signal that `OPENROUTER_API_KEY` in a
root `.env` is required, or how to start the two services.

**Action:** add `.env.example` with `OPENROUTER_API_KEY=` and a short root
`README.md` (prereqs, `dotnet run` + `npm run dev`, ports, test commands).

### M11. No CI
Tests exist on both sides but nothing runs them. Regressions (like the broken
E2E spec) go unnoticed.

**Action:** add a GitHub Actions workflow: `dotnet test` for the backend,
`npm ci && npm test && npm run build` for the frontend. Add Playwright as a
second job once H4 is fixed.

## Low / polish

### L1. `frontend/tsconfig.tsbuildinfo` is committed
Incremental-build cache. Add `*.tsbuildinfo` to `frontend/.gitignore` and
`git rm --cached frontend/tsconfig.tsbuildinfo`.

### L2. Root `.gitignore` is three lines
`.env`, `bin/`, `obj/` only. Backend `bin/`/`obj/` are covered; DB files,
`*.tsbuildinfo`, and any stray `.next/` outside `frontend/` are not. Fold in the
C1/L1 patterns.

### L3. `UpdateMember` calls `db.Members.Update(member)` needlessly
`backend/Program.cs:141` - the entity is already tracked from `FindAsync`, so
`SaveChangesAsync` persists the field assignments. `Update` marks the whole
entity modified. Remove the line.

### L4. Dead DB infrastructure - Surname index
`ApplicationDbContext.cs:45` creates `IX_Members_Surname`, but nothing in the API
searches or sorts by surname. Remove until there is a query that needs it.

### L5. Backend max-length constraints are not enforced
`HasMaxLength(100)`/`(20)` in `OnModelCreating` - SQLite ignores column length,
and `ValidateMember` does not check length, so a 10,000-char `firstName` is
accepted. Either add length checks to `ValidateMember` or drop the `HasMaxLength`
calls so the code does not imply a guarantee it lacks.

### L6. `Button` ignores `children` while loading and hardcodes "Processing..."
`components/Button.tsx:54-58`. `MemberForm` passes
`isLoading ? 'Processing' : 'Submit'` as children *and* relies on this - so the
label is handled in two places and cannot be customised.

**Action:** render `children` next to the spinner; drop the hardcoded text.

### L7. `types/Member.ts` `ApiResponse<T>` is unused
Dead export. Remove, or use it to type the service responses.

### L8. `aiService.AIResponse.member` type is inaccurate
Marks `firstName`/`surname`/etc. as required though `delete`/`edit` responses
send only `id` (+ changed fields). Make them optional to match runtime and the
prompt contract.

### L9. Duplicated `BACKEND_API_URL` constant
Same declaration with the same fallback in `api/members/route.ts` and
`api/members/[id]/route.ts`. Extract to `src/lib/backend.ts` (or similar).

### L10. `members/[id]` proxy DELETE returns a body with 204
`Response.json({}, { status: 204 })` - HTTP 204 must not have a body. Use
`new Response(null, { status: 204 })`.

### L11. `vitest.setup.ts` and test files both assign `global.fetch = vi.fn()`
Redundant. Keep it in the setup file only.

### L12. `frontend/tsconfig.json` carries Vite-template cruft
`declaration`, `declarationMap`, `sourceMap`, `useDefineForClassFields`,
`allowImportingTsExtensions` with `target: ES2020` - irrelevant under Next's
`noEmit`. Align with the Next 15 default tsconfig.

### L13. `.eslintrc.json` is the deprecated format for ESLint 9
`next lint` still reads it in Next 15 but this is on the way out. Migrate to
`eslint.config.mjs` (flat config) when convenient. Also note `next lint` itself
is deprecated in favour of the ESLint CLI in newer Next.

### L14. Hardcoded `en-US` locale in `formatDate`
The data is UK (postcodes, `+44` numbers) but dates render "May 15, 1980". Use
`en-GB` or make it a parameter.

### L15. `formatDate` timezone note
Constructing `new Date(year, month-1, day)` gives local midnight - correct here
and deliberately avoids UTC-shift bugs. No change needed; keep the comment.

### L16. `MemberList` is a table with horizontal scroll on mobile
`AGENTS.md` asks for mobile-responsive. `overflow-x-auto` is the minimum bar; a
stacked-card layout under `sm:` would be the real fix. Low priority for MVP.

### L17. `tailwind.config.ts` content glob references `./src/pages/**`
No `pages/` directory exists (App Router). Harmless, remove the line.

### L18. Backend `CreatedAt` vs `UpdatedAt` set from different clocks
`CreatedAt` comes from the `Member` property initializer (construction time);
`UpdatedAt` is set in `UpdateTimestamps` at SaveChanges time. Values differ
slightly on create. For consistency, set both in `UpdateTimestamps` for the
`Added` state and drop the property initializers.

### L19. Dead CORS configuration
The `AllowFrontend` policy is never exercised because the browser only ever
calls the same-origin Next proxy. It is a harmless safety net; keep it only if
you expect direct browser-to-API calls later, otherwise remove per the
simplicity standard.

### L20. Commit message quality
"Claude nade the changes", "modified", "removed", "updated commit" - not
actionable history. Adopt short imperative summaries.

## Testing gaps

### T1. Backend endpoint tests (`MembersEndpointsTests.cs`)
Missing cases:
- `GET /api/members/{id}` **success** (only the 404 path is tested).
- `PUT` with an **invalid body** -> 400 (only 404 and success tested).
- Response envelope shape (`{ data: ... }`) and that `createdAt`/`updatedAt` are
  populated.
- `GET /health`.
- Whitespace-only fields (`"   "`) are rejected.

### T2. Backend test isolation
`MembersEndpointsTests` is one `IClassFixture` instance -> one SQLite file shared
by all tests in the class. `CreateMember_ValidData_ReturnsCreated` leaves a row
behind. It works today only because assertions use `>= 5`. Prefer a fresh DB per
test (respawn the factory, or wrap each test in a transaction/cleanup) so future
count-based assertions are safe.

### T3. Frontend - untested units
- `/api/chat` route: JSON passthrough, fenced-JSON (H1), non-JSON fallback,
  missing API key -> 500.
- `/api/members` and `/api/members/[id]` proxy routes: success and
  error-forwarding.
- `ChatSidebar`: `applyAiAction` for each of create/edit/delete, and the
  `members:changed` dispatch.
- `dateFormatter`: once simplified (M5), one happy-path + empty-string test.

### T4. Frontend E2E
After H4, add specs for: add member (form -> list), edit member, delete member
(modal -> gone), and an AI-chat create with `/api/chat` stubbed. Run against a
real or stubbed backend via `webServer`.

### T5. Coverage thresholds
`vitest.config.ts` collects coverage but sets no minimums. Once T3 lands, add
modest thresholds (e.g. 70%) so coverage cannot silently regress.

## What is good (keep)

- The proxy architecture (browser -> Next API routes -> backend/OpenRouter) is
  the right call: no CORS, key stays server-side. Cleanly implemented.
- Secret handling is correct - `.env` gitignored, loaded server-side only, read
  in exactly one file, never logged.
- Backend is genuinely minimal: one file, one shared `ValidateMember`, no
  premature service/repository layers.
- `Program.cs` exposes `public partial class Program` purely for
  `WebApplicationFactory` - the right testing seam.
- `formatDate` deliberately avoids the classic `new Date("YYYY-MM-DD")` UTC-shift
  bug (L15).
- `docs/PLAN.md` (as-built) and `CLAUDE.md` are accurate and useful.
- EF Core parameterisation - no SQL injection surface.
- `Input` uses `useId` for label association.
